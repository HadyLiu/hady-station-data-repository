# 技术选型与零散备忘

## 1. 跨平台 GUI 方案

做需要同时跑 Windows / Linux / macOS 的上位机工具时，候选方案与取舍：

| 方案 | 语言 | 优点 | 代价 |
| --- | --- | --- | --- |
| **egui / eframe** | Rust | 即时模式，代码即界面，无需布局文件；打包单文件 | 默认字体对中文支持需手动加；原生控件观感一般 |
| **Slint** | Rust / C++ / JS | 声明式 DSL，界面与逻辑分离；嵌入式可跑（no_std） | 生态较小，复杂控件需自绘 |
| **Tauri** | Rust + Web | 复用前端技能，生态最全；体积比 Electron 小 | 依赖系统 WebView，版本差异需测 |
| **纯网页（本地服务）** | 任意 | 零安装，手机也能看；调试最简单 | 需起本地端口，串口/文件访问受限 |
| **Qt / QML** | C++ / Python | 控件最成熟，工业上位机主流 | 部署体积大，许可证需注意 |

选择建议：

- 要**和硬件打交道**（串口、USB）且只在自己机器跑 → egui / Slint
- 要**给别人用、界面复杂** → Tauri 或 Qt
- 只是**看数据、调参数** → 本地起个网页最省事

## 2. 嵌入式杂项经验

- **单次采样不可靠**：模拟量要分布采样（多次平均或中值滤波），别信一次 ADC 读数。
- **过采样 / 欠采样**：过采样 + 平均能提升有效位数；欠采样用于周期性信号，注意混叠。
- **休眠唤醒不能当判断依据**：唤醒源可能误触发，主循环里仍要做状态确认算法。
- **I2C 电平不匹配**（5V 主 → 3.3V 从）可能表现为"完全不通"而不是通信错误，先量电平。
- **分层架构**：GPIO 初始化集中在一个文件，模块初始化分散到各自模块，避免一个 `bsp_init()` 包打天下。
- **触摸弹簧接触面积变小会变慢**：机械结构影响灵敏度，调试时先排除结构因素。

## 3. 常用端口与设备命名

| 平台 | 串口命名 | 说明 |
| --- | --- | --- |
| Windows | `COM3`、`COM28` | 编号不固定，插拔后可能变，用 `usbipd list` / 设备管理器确认 |
| Linux | `/dev/ttyUSB0` | USB 转串口（CH340、CP210x） |
| Linux | `/dev/ttyACM0` | 原生 USB CDC（ESP32-C3/S3、STM32 USB） |
| macOS | `/dev/tty.usbserial-*` | — |

端口号写进脚本是大坑，尽量用 udev 规则做固定软链（`/dev/ttySENSOR`）。

## 4. 文件被 Windows 锁定

从网络下载的 exe / 脚本双击提示「无法运行」「已被系统阻止」，是 NTFS 的 Zone.Identifier 标记：

右键 → 属性 → 底部勾选 **解除锁定** → 确定。

批量处理（PowerShell）：

```powershell
Get-ChildItem .\*.exe | Unblock-File
```

## 5. 笔记与凭证的边界

- 密码、token、恢复码、私钥**一律不进笔记库**，用密码管理器。
- 笔记里只留「怎么生成」「放哪查」，不留值。
- 需要分享笔记时，先按 [脱敏说明](../脱敏说明.md) 扫一遍：路径、用户名、IP、域名、客户名。
